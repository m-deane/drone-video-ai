**The sibling agents' corpus-wide pattern holds for my slice, with zero exceptions and one

File B is the aggravating detail: it uses a **numbered** reference format `[1]`…`[15]`, which
visually signals a citation apparatus, but **not one of those numbers is ever referenced from
the body**. The list is decorative. A reader skimming file B would reasonably infer that its
claims are cited; none are. That is a stronger failure than file A's, which at least does not
pretend — file A simply appends a bare bullet list of links.

Consequently, of the 94 numeric editorial claims in this slice, **0 carry a resolvable named
source for that specific number**. Two carry vague, unresolvable gestures — "(studies show
this range is most engaging)" for the 100-130 BPM target (A:96) and "(TikTok data)" for the
+55%/40% typography figures (B:170) — and I have deliberately NOT upgraded either into a named
source, per instruction. The bulk lists are topically adjacent to many claims (e.g. two AAA
Presets LUT-forecast URLs sit near the LUT-intensity claims), but topical adjacency is not
citation, and no line in either document asserts the linkage.

The one place a source name appears *in the body at the point of assertion* is A:218
("SkyPixel 10th Annual Contest (2025)") governing A:219's 140,000-entries figure — and that
figure is a contest statistic, not an editorial claim about the output video, so it does not
enter the register. The identical structure at A:245 ("NYC Drone Film Festival insights")
governs no number at all.

**Bottom line for this project.** Nothing in this slice can ground a threshold. Every number is
either bare, vaguely gestured at, self-labelled as "suggested calibration" (A:265), or
contradicted by another number in the same two files. Sixteen distinct contradictions were
found across 666 lines. If any constant in `drone_video_ai` traces to either of these files,
